# ParkDesk Phase 0 검사 페이지

테슬라 내장 브라우저와 노트북이 **휴대폰 핫스팟(사설 IP LAN)** 에 같이 붙어 있을 때, 아래가 되는지를 확인하기 위한 정적 페이지입니다.

- 테슬라가 **공개 HTTPS 페이지**를 열 수 있는가
- **시그널링은 인터넷**(공개 브로커)으로 가는가
- **영상/데이터는 핫스팟 LAN 안에서 WebRTC 직접(host 후보) 연결**이 되는가
- 테슬라 브라우저가 사설 IP URL을 막는지, WebRTC·H.264·터치를 지원하는가

코드는 빌드 없이 `index.html` + `app.js` + `styles.css`만 있으면 됩니다. `DESIGN.md`는 이 폴더에서 수정하지 않았습니다.

주차(P) 상태에서만 사용하세요. 주행 중에는 열지 마세요.

## 준비

1. 차량을 **주차(P)** 합니다.
2. Galaxy 휴대폰에서 **모바일 핫스팟**을 켭니다.
3. **노트북**과 **테슬라**가 그 핫스팟 Wi-Fi에 접속하게 합니다. (회사 PC의 Windows 모바일 핫스팟은 쓰지 않습니다.)
4. 노트북이 핫스팟 인터넷으로 이 검사 페이지에 접근할 수 있는지 확인합니다. 테슬라도 같은 공개 HTTPS URL을 엽니다.

## 호스팅

이 페이지는 **반드시 공개 HTTPS**로 열려야 합니다. 테슬라 브라우저는 사설 IP 주소창 접속을 막는 것으로 알려져 있고, WebRTC도 보안 컨텍스트(HTTPS)가 안전합니다.

가장 간단한 방법:

1. GitHub에 빈 저장소를 하나 만듭니다.
2. 이 `phase0` 폴더의 파일(`index.html`, `app.js`, `styles.css`, `peerjs.min.js`)을 저장소 **루트**에 올립니다.
3. Settings → Pages → Source를 `main`(또는 기본 브랜치) / `/ (root)`로 켭니다.
4. 몇 분 뒤 `https://<계정>.github.io/<저장소>/` 가 생깁니다. 테슬라 북마크에 이 주소를 저장해 두면 편합니다.

GitHub Pages 외에 Netlify Drop, Cloudflare Pages처럼 정적 파일을 올리는 HTTPS 호스트도 됩니다. **상대 경로만 쓰므로 하위 경로에 올려도 됩니다.** 예: `https://<계정>.github.io/<저장소>/phase0/`

로컬 확인만 할 때는 노트북에서:

```bash
cd phase0
python3 -m http.server 8080
```

브라우저로 `http://127.0.0.1:8080/` 을 엽니다. 로컬 HTTP는 테슬라 검사용이 아닙니다.

## 시그널링 의존성 (PeerJS 클라우드)

페어링은 계정 없이 쓰는 **PeerJS 공개 브로커 `0.peerjs.com`** 으로 합니다. 라이브러리 `peerjs.min.js`(v1.5.4, MIT)는 이 폴더에 포함되어 있어, 페이지 로드 시 CDN은 필요하지 않습니다. 다만 **연결 순간에 `0.peerjs.com`으로의 인터넷 접속**이 필요합니다(핫스팟 데이터 사용).

- 이 브로커는 제3자 서비스라 지연, 속도 제한, 장애가 날 수 있습니다.
- STUN은 `stun:stun.l.google.com:19302` 입니다.
- TURN은 PC에서 붙입니다. 계정 없이 지금 동작하는 공개 TURN은 없습니다. 아래 “TURN 준비”를 보세요.

## TURN 준비

2026-11-26에 이 환경에서 직접 확인했습니다.

- PeerJS 기본 릴레이 `turn:eu-0.turn.peerjs.com:3478`, `turn:us-0.turn.peerjs.com:3478` 는 DNS 레코드가 없고, 브라우저 ICE도 `host lookup` 오류만 냈습니다. relay 후보 0개.
- Metered Open Relay의 예전 공개 계정(`openrelay.metered.ca`, `openrelayproject`)은 더 이상 릴레이되지 않습니다. 호스트는 문서용 주소로 빠져 있고, ICE에서도 relay 후보가 나오지 않았습니다. 지금은 무료 계정과 API 키가 필요합니다.
- 예전에 돌던 ExpressTURN 데모 계정은 `401 Unauthorized` 였습니다.

그래서 **가입 없이 쓸 수 있는 TURN은 이 페이지에 넣지 않았습니다.** 비밀번호를 저장소에 적지도 않습니다. PC 화면에 붙여 넣은 값은 그 브라우저의 `localStorage`에만 있고, 페어링할 때 테슬라로 시그널링 메타데이터로만 전달됩니다.

회사 노트북 방화벽을 통과하려면 **`turns:` + TCP/TLS 443** 을 우선하고, 가능하면 `turn:` UDP/TCP도 같이 넣으세요.

### Metered Open Relay (이 정적 페이지에서 가장 단순한 무료 한도)

1. [Open Relay](https://www.metered.ca/tools/openrelay/)에서 무료 계정을 만듭니다.
2. 앱을 만들고 API 키를 받습니다. 무료 한도는 월 20GB입니다.
3. 브라우저에서 `https://<앱이름>.metered.live/api/v1/turn/credentials?apiKey=<API_KEY>` 를 엽니다.
4. 응답의 `urls`, `username`, `credential` 을 PC 화면의 TURN 칸에 붙여 넣습니다. `urls`에 `turns:` 와 443이 있으면 그 주소를 포함하세요. 여러 URL은 줄바꿈으로 넣습니다.
5. **TURN 저장**을 누른 뒤 **TURN 서버 확인**을 누릅니다. relay 후보가 1개 이상이면 이 노트북에서 TURN에 도달한 것입니다.

API 키는 페이지 소스에 넣지 마세요. 자격 증명은 짧은 시간만 유효할 수 있으니, 확인이 실패하면 3번 URL을 다시 열어 새 값을 붙이세요.

### Cloudflare Realtime TURN

1. Cloudflare에 가입하고 Realtime TURN 키를 만듭니다. 첫 1,000GB/월은 SFU와 함께 무료입니다.
2. TURN 키는 서버에만 두고, `https://rtc.live.cloudflare.com/v1/turn/keys/$TURN_KEY_ID/credentials/generate-ice-servers` 로 짧은 수명의 `iceServers`를 만듭니다. 정적 페이지에 키를 넣으면 안 됩니다.
3. 응답의 `turns:turn.cloudflare.com:443?transport=tcp` 와 username, credential을 PC 화면에 붙여 넣습니다.

백엔드를 만들기 어렵으면 Metered 쪽이 이 테스트에는 더 짧습니다.

## 검사 절차

### A. 노트북(PC)

1. 호스팅된 URL을 Edge 또는 Chrome으로 엽니다.
2. **PC**를 고르거나, `?role=pc` 로 엽니다.
3. 큰 글씨로 **6자리 페어링 코드**가 나타납니다. 브로커에 “코드 대기 중”이 되면 준비된 것입니다. 브로커가 끊겨도 이 코드는 유지되고 같은 ID로 다시 붙습니다.
4. **TURN 서버 확인**을 먼저 누릅니다. relay 후보가 없으면 차까지 가지 말고 TURN URL을 고칩니다.
5. 연결 방식을 **직접만**으로 두고 한 번 시험합니다. 회사 방화벽이 P2P를 막으면 후보 쌍이 없거나 `unknown`이고, 테슬라 결과가 오지 않을 수 있습니다. ICE 타임라인에 `iceConnectionState` 가 남습니다.
6. 그다음 **중계만**으로 바꿉니다. 테슬라는 PC가 보낸 같은 설정을 씁니다. 후보 쌍이 `relayed (TURN)` 인지 확인합니다.
7. DataChannel RTT의 p50/p95를 확인합니다.
8. (선택) **화면 공유 시작**을 누르고, 창이나 화면을 고릅니다. 테슬라에 영상이 뜨는지, fps·해상도를 봅니다.
9. **테슬라 결과** 카드에 수신 요약이 보이면 테슬라 JSON이 도착한 것입니다.
10. **결과 JSON 복사**는 PC 결과와 테슬라 결과를 `{ "pc": ..., "tesla": ... }` 한 덩어리로 복사합니다. **JSON 파일로 저장**은 같은 내용을 `.json` 파일로 받습니다. 테슬라 결과가 아직 없으면 `tesla`는 `null`입니다. JSON의 `iceTimeline` 에 상태 변화와 후보가 들어 있습니다. TURN 비밀번호는 들어 있지 않습니다.

### B. 테슬라

1. 같은 URL을 테슬라 브라우저로 엽니다. (주소는 공개 HTTPS여야 합니다.)
2. **테슬라**를 고르거나 `?role=tesla` 로 엽니다. 큰 버튼을 쓰기 쉽게 만들어 두었습니다.
3. 페이지가 열리면 환경(UA, 화면 크기, devicePixelRatio), WebRTC/DataChannel 지원, H.264 수신 여부, ICE 후보 수집이 **자동으로** 실행됩니다.
4. (선택) 노트북의 핫스팟 IPv4를 넣어 **사설 IP 검사**를 누릅니다. 노트북 IP는 Windows에서 `ipconfig`의 핫스팟 어댑터 IPv4입니다.
5. 노트북에 보이는 6자리 코드를 입력하고 **연결**을 누릅니다. PC가 테슬라로 연결을 걸고, 연결 방식과 TURN 정보를 같이 보냅니다. 테슬라의 자동/중계만/직접만 버튼은 PC 값이 오면 그 값으로 바뀝니다.
6. 영상이 나오면 화면을 탭합니다. 노트북에 점이 찍히면 터치 역방향이 된 것입니다.
7. 연결되면 전체 결과가 PC로 자동 전달됩니다. 화면 공유나 탭 뒤에 **PC로 결과 보내기**를 누르면 그 시점의 전체 JSON이 다시 갑니다. 차량의 **결과 JSON 복사**는 테슬라 브라우저 안에만 남습니다.
8. ICE가 실패하면 **사진으로 남길 요약**이 큰 글씨로 나옵니다. 모드, `iceConnectionState`, host/srflx/relay 개수, 선택된 쌍이 들어 있습니다. 휴대폰으로 그 칸을 찍으세요. 브로커만 끊긴 경우에는 코드를 유지한 채 다시 붙으므로, 그 순간에는 사진 요약을 띄우지 않습니다.
9. 노트북에서 합친 JSON을 복사하거나 파일로 저장해 채팅에 붙여 주시면 설계에 반영할 수 있습니다.

`?role=tesla&code=AB12CD` 처럼 코드를 URL에 넣으면 입력칸만 미리 채워집니다. 연결은 직접 **연결**을 눌러 주세요.

## 결과를 노트북으로 가져오기

테슬라의 **결과 JSON 복사**는 차량 브라우저 안에서만 복사됩니다. 노트북으로 옮기려면 DataChannel로 보냅니다.

- DataChannel이 열리면 테슬라가 **전체 결과 JSON**(복사 버튼과 같은 `snapshot`)을 **자동으로 한 번** 보냅니다. 환경, 코덱, ICE뿐 아니라 `privateIpTest`, 미디어 통계, 탭, 로그, 오류가 그 시점에 들어 있으면 함께 갑니다.
- 그 뒤에 검사가 끝나면 **한 번 더** 보냅니다. 자동 ICE 수집이 채널이 열린 뒤에 끝날 때, 후보 쌍이 성공(`succeeded`)할 때, 사설 IP 검사가 끝날 때입니다.
- 글자가 길면 약 3500바이트 조각으로 나눠 보내고, PC가 순서대로 다시 합칩니다.
- **PC로 결과 보내기**는 DataChannel이 열린 뒤에만 눌립니다. 화면 공유와 탭까지 넣은 최신 스냅샷을 보낼 때 누릅니다.
- PC는 받은 테슬라 결과를 **테슬라 결과** 카드에 저장해 보여 줍니다.
- PC의 **결과 JSON 복사**와 **JSON 파일로 저장**은 둘 다 `{ "pc": { ... }, "tesla": { ... } }` 입니다.
- ICE가 실패하면 테슬라에 모드, WebRTC, H.264, ICE 상태, relay 개수, 선택된 쌍을 큰 글씨로 보여 줍니다. 휴대폰으로 그 칸을 찍는 폴백입니다.

## 결과가 뜻하는 것

| 결과 | 설계에 주는 의미 |
|---|---|
| 테슬라가 공개 HTTPS 페이지를 연다 | 회사 PC 핫스팟을 못 켜도, 폰 핫스팟 + 공개 페이지만으로 시작점을 만들 수 있다 |
| `RTCPeerConnection` / DataChannel / H.264 수신이 “지원·있음” | 브라우저 뷰어 + H.264 WebRTC 경로가 Y L에서 성립한다 |
| ICE에 `host` 후보가 있고, 주소가 `192.168/10/172.16` 같은 사설 대역이다 | 브라우저는 URL로는 사설 IP를 막아도, **ICE 후보는 사설 주소를 수집**할 수 있다 |
| ICE 후보가 `*.local` mDNS만 있다 | 사설 IP가 가려진 것. 같은 LAN이면 직접 연결이 될 수도, 안 될 수도 있으니 페어링 결과로 판단한다 |
| ICE에 `srflx`만 있고 host가 없다 | LAN 직접 연결이 어려울 수 있다. STUN/TURN 의존도가 커진다 |
| 페어링 후보 쌍이 **host-to-host (같은 LAN)** | 목표 구조가 검증된 것. 시그널링만 인터넷, 미디어는 핫스팟 안에서 직접 |
| 후보 쌍이 **srflx/prflx** | 연결은 됐지만 패킷이 NAT/STUN 쪽으로 나갔을 수 있다. 지연·데이터 사용을 더 봐야 한다 |
| 페어링 자체가 실패 | 브로커 장애, 테슬라 WebSocket 제한, ICE 실패 등을 로그로 구분해야 한다. TURN이 없는 상태에서의 실패일 수 있다 |
| DataChannel RTT p50이 수십 ms 이내 | 터치 입력 채널로 쓸 만하다. 100ms 화면 지연 예산에 여유가 생긴다 |
| 화면 공유 fps가 낮거나 끊김 | 인코딩/디코딩·MCU 성능 한도. 해상도 30fps 상한 설계에 반영 |
| 탭 좌표가 PC 보드에 표시 | 터치 → DataChannel → 노트북 경로가 성립. 이후 SendInput만 붙이면 된다 |
| 사설 IP `fetch`/`img` 실패 | **예상되는 결과일 수 있다.** 이 페이지는 HTTPS라 HTTP 사설 주소는 혼합 콘텐츠로도 막힌다. 테슬라가 특별히 사설 대역을 차단하는지는, 주소창에 `http://<노트북IP>` 를 **직접 입력**한 결과와 비교해야 한다 |

사설 IP를 주소창에 직접 넣는 보조 검사(선택):

1. 노트북에서 `python3 -m http.server 8080` 을 켠다.
2. 테슬라 주소창에 `http://192.168.x.x:8080/` 을 입력한다.
3. 접속되면 “사설 IP URL 허용”, Access Denied / 실패면 “사설 IP URL 차단”으로 적는다. 이 결과는 JSON의 페이지 안 검사보다 테슬라 정책에 더 가깝습니다.

## 제한

- 가입 없이 동작하는 TURN은 현재 없습니다. 중계 시험은 PC에 붙여 넣은 TURN이 relay 후보를 만들 때만 의미가 있습니다.
- PeerJS 클라우드가 다운되거나 속도 제한에 걸리면 페어링이 실패할 수 있습니다.
- 테슬라 클립보드는 차량 안에 남을 수 있습니다. DataChannel로 PC에 보내고, 페어링이 실패하면 사진 요약을 찍습니다.
- 화면 공유는 노트북 브라우저의 `getDisplayMedia`에 의존하며, 테슬라 쪽에서는 할 수 없습니다.
- HTTPS 페이지의 사설 HTTP 검사는 혼합 콘텐츠와 테슬라 사설 IP 차단이 섞여 보일 수 있습니다.
